# 最终答辩演示清单

## 演示准备

1. 在 `frontend/` 执行 `npm run dev`，使用 Chrome 打开终端显示的地址。
2. 确认顶部显示“离线演示模式”。若后端已启动，显示混合模式也不影响业务闭环。
3. 三个演示账号密码均为 `Demo123!`：`user_demo`、`merchant_demo`、`admin_demo`。
4. 若上次演示残留数据，清除该站点的 `localStorage` 后刷新。

## 开场定位

用一句话介绍：这是聚焦德昂族酸茶的“非遗科普 + 互动体验 + 电商转化”平台，不是泛茶文化网站。

核心链路：认识酸茶 -> 互动生成配方 -> 预约工坊 -> 购买商品 -> 商家履约 -> 平台监管。

## 普通用户

1. 浏览首页、酸茶科普、制作工艺和传承故事，打开一篇带来源的内容详情。
2. 进入“互动体验”，完成三步选择并保存配方海报。
3. 登录 `user_demo`，在商城购买“酸茶体验装”。填写收货信息并创建订单。
4. 先点击“支付失败”，展示可恢复的待支付状态；再点击“支付成功”。
5. 创建工坊预约，记录生成的 `BOOK-` 核销码。
6. 展示个人中心的订单、预约、海报与售后列表。

## 商家

1. 登录 `merchant_demo`，查看经营看板。
2. 新建“答辩限定酸茶体验装”，保存并提交审核，确认状态为“待审核”。
3. 在订单管理中找到待发货订单并确认发货。
4. 在售后管理中填写处理说明，通过申请并完成模拟退款。

## 管理员

1. 登录 `admin_demo`，查看平台数据看板。
2. 在商家审核中通过一条待审申请。
3. 在商品审核中通过商家刚提交的商品。
4. 在内容管理中新建酸茶科普，填写来源机构、网址和支持内容后“保存并发布”。
5. 在预约核销中输入普通用户生成的 `BOOK-` 码并确认核销。

## 闭环收尾

再次登录 `user_demo`，展示订单时间线、售后退款时间线与“已核销”预约。说明三类身份共享同一套本地演示状态，因此可以连续完成跨角色闭环。

## 讲解边界

- A 方案混合模式只从 Java API 读取已发布科普内容，其余可变流程使用完整本地演示数据。
- 模拟支付与退款不发生真实资金交易。
- MySQL、真实支付、生产级身份认证和对象级权限属于后续工程化范围。
