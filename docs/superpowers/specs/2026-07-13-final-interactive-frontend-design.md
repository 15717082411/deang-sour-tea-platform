# 德昂族酸茶平台最终交互前端设计规格

## 1. 背景与目标

当前 `frontend/` 是由 `index.html`、`styles.css` 和 `app.js` 组成的静态 MVP。它能够演示基本流程，但缺少组件边界、真实路由、正式账户入口、完整状态反馈、响应式工作台和可测试的数据层。本轮将前端迁移为 Vue 3 + Vite 单体应用，形成可用于毕业设计提交和现场答辩的最终可交互版本。

产品定位保持为“德昂族酸茶非遗科普、互动体验与电商转化平台”，只聚焦德昂族酸茶，不扩展为泛茶文化门户。

成功标准：普通用户、商家、管理员三类身份均有完整可操作路径；订单、模拟支付、发货、收货、售后、商家审核、商品审核和预约核销均可重复演示；后端不可用时仍可通过离线演示模式完成全部答辩流程。

## 2. 范围边界

本轮负责完整的前端产品化升级，以及对现有 Spring Boot API 的兼容接入。前端会完整建模账户和交易状态，但不会将客户端权限限制描述成生产级安全。真实身份认证、密码存储、用户与资源归属校验、支付签名、库存并发和退款清算仍属于后端后续工作。

不接入真实支付渠道，不上传真实个人信息，不建设多商户结算、物流平台对接、即时通信或复杂推荐算法。

## 3. 技术方案

- Vue 3、TypeScript、Vite。
- Vue Router 管理公共端、用户中心、商家中心和管理后台路由。
- Pinia 管理认证、目录、购物车、订单、预约、商家审核和全局界面状态。
- Axios 封装 Spring Boot API；仓库接口隔离在线和演示数据源。
- Element Plus 用于工作台表单、表格、对话框和反馈组件；公共文化端使用定制组件和样式。
- Lucide Vue Next 提供功能图标；ECharts 提供经营和平台看板图表。
- Vitest、Vue Test Utils 和 Playwright 组成自动化测试体系。
- ESLint、Prettier 和 `vue-tsc` 负责静态检查。

应用保持一个构建工程，按布局和路由拆分三套工作区，不拆成三个独立前端项目。

## 4. 信息架构与路由

### 4.1 公共端

| 路由 | 页面职责 |
| --- | --- |
| `/` | 非遗叙事首页，呈现酸茶、制作技艺、互动与商品入口 |
| `/culture` | 酸茶文化内容聚合 |
| `/culture/:slug` | 内容详情与可追溯来源 |
| `/craft` | 杀青、揉捻、装筒发酵、品饮工艺时间轴 |
| `/stories` | 传承人物与工坊故事 |
| `/journey` | “茶魂寻踪”分步互动与配方卡生成 |
| `/shop` | 商品搜索、分类、排序和筛选 |
| `/shop/:id` | 商品详情、规格、库存和购买操作 |
| `/cart` | 购物车数量调整、删除和金额计算 |
| `/checkout` | 收货信息、订单确认和库存复核 |
| `/payment/:orderId` | 模拟支付成功、失败和取消 |
| `/booking` | 工坊日期、人数、联系方式和预约记录 |
| `/login`、`/register` | 账户登录和注册 |
| `/merchant/apply` | 商家入驻申请及审核状态 |

### 4.2 用户中心

`/account` 使用用户中心布局，包含资料概览、订单列表与详情、预约记录、互动配方卡、售后申请与进度。游客访问受限页面时跳转登录，并通过 `redirect` 参数返回原目标。

### 4.3 商家中心

`/merchant` 使用高密度侧边栏布局，包含经营看板、商品列表、商品编辑与提交审核、订单列表与发货、售后处理。只有审核通过的商家可以进入；待审核或驳回用户进入状态说明页。

### 4.4 管理后台

`/admin` 使用独立管理布局，包含平台看板、商家审核、商品审核、文化内容管理和预约核销。管理员路由只对 `ADMIN` 开放。

未知路由进入 `404`，已登录但越权进入 `403`。导航不再提供角色下拉框，改为登录入口、头像菜单和按角色显示的工作台入口。

## 5. 视觉与交互设计

公共端采用已确认的“A：非遗叙事型”方向。首屏以德昂族酸茶制作场景为第一视觉信号，标题直接使用“德昂族酸茶”，并在首屏底部露出下一段内容。页面使用炭黑、茶叶绿、发酵红、纸白和少量铜金，避免单一棕色或米黄色主题。文化标题使用中文衬线字体，正文和工作台使用无衬线字体，字距保持为 0。

视觉资产包括原创主视觉、工艺过程图、茶叶与竹筒发酵细节、商品主图和人物故事占位素材。生成图不作为历史证据，文化事实必须在内容详情页列明权威来源、标题和访问链接。

公共端采用全宽叙事段落、时间轴和商品网格；商家与管理后台采用克制、高密度的筛选栏、表格和图表。卡片圆角不超过 8px，不嵌套卡片。图标按钮使用 Lucide 图标并提供工具提示。

关键组件包括全局导航、移动端抽屉、头像菜单、面包屑、内容条目、工艺时间轴、商品卡、数量步进器、购物车摘要、订单进度、模拟支付面板、状态标签、数据表格、筛选分页、空状态、骨架屏、错误提示、确认对话框和消息通知。

## 6. 数据架构与双模式

组件和 Pinia Store 不直接调用 Axios 或 `localStorage`，而是依赖统一仓库接口：

```text
Vue 页面/组件
      ↓
Pinia Stores
      ↓
Repository Interfaces
   ↙           ↘
ApiRepository  DemoRepository
Spring Boot    versioned localStorage
```

启动时检测 API 健康状态。API 可用时优先使用 `ApiRepository`；接口不可用或某项能力尚未实现时，显示明确的模式提示，并由用户确认切换到演示模式。错误不得被静默吞掉。演示数据包含版本号，数据结构升级时执行迁移或重建；设置页提供一键恢复答辩初始场景。

现有后端只同步已支持的商品、内容、订单、预约、商家和看板接口。注册、商家申请、支付细分状态、收货与售后等未支持能力由 `DemoRepository` 完整实现，并在界面持续标记“演示环境”。

## 7. 身份与权限模型

身份包括 `GUEST`、`USER`、`MERCHANT` 和 `ADMIN`。账户保存唯一 ID、用户名、展示名、联系方式、角色和状态。演示环境提供三类预置账号，同时允许注册普通用户。

商家流程为：普通用户提交入驻资料，状态变为 `PENDING`；管理员可以通过或驳回；通过后用户获得商家工作台权限。商家只读取与自身 `merchantId` 匹配的商品、订单和售后数据。前端路由守卫和仓库层同时校验角色及资源归属，但规格明确要求真实部署时后端重复校验。

## 8. 业务状态机

### 8.1 商品

```text
DRAFT → PENDING → APPROVED → OFF_SHELF
                 ↘ REJECTED → DRAFT
```

商家保存草稿或提交审核；管理员通过或驳回并记录意见；只有 `APPROVED` 商品对公共商城可见。

### 8.2 订单与支付

```text
PENDING_PAYMENT → PAID → SHIPPED → RECEIVED → COMPLETED
       ↓            ↓        ↓
   CANCELLED     AFTER_SALE_REQUESTED
```

结算时重新校验库存和金额。模拟支付支持成功、失败和取消；失败后订单保持待支付，可重新支付。操作按钮在请求期间禁用，防止重复提交。支付成功后扣减库存并生成时间线。

### 8.3 售后

```text
REQUESTED → PROCESSING → APPROVED → REFUNDED → CLOSED
                         ↘ REJECTED → CLOSED
```

用户填写原因并提交；商家同意或拒绝；同意后触发模拟退款。每次状态变化记录时间和处理说明。

### 8.4 预约

```text
PENDING → VERIFIED
    ↘ CANCELLED
```

用户选择未来日期、人数和联系方式后获得核销码；管理员输入或选择核销码完成核销。已核销和已取消记录不可再次操作。

## 9. 校验、错误和可访问性

表单校验覆盖必填项、手机号、日期、人数、金额和库存范围。库存不足、数据为空、API 离线、权限不足、资源不存在和状态冲突均有独立反馈。破坏性操作使用确认对话框，成功操作使用消息提示，页面级失败提供重试按钮。

交互元素支持键盘操作和可见焦点；图像提供替代文本；颜色不是状态的唯一表达方式；正文与背景满足基本对比度。移动端保持 44px 左右可点击区域，表格在窄屏转换为列表，页面不得出现横向溢出和文字遮挡。

## 10. 测试与验收

Vitest 覆盖金额计算、库存校验、路由权限和各状态机；Vue Test Utils 覆盖登录、购物车、支付、审核和核销组件；Playwright 覆盖三类身份端到端路径。构建门槛包括 `lint`、`typecheck`、`test` 和 `build` 全部通过。

浏览器验收视口为 `1440×900`、`768×1024` 和 `390×844`。检查首页主视觉、导航、商城、结算、工作台表格、弹窗和移动端抽屉，不允许出现空白画布、无效按钮、内容重叠或不可恢复的流程中断。

必须通过以下演示链路：游客浏览文化内容；用户注册并完成互动；购物车结算；模拟支付失败后重试成功；用户申请商家；管理员审核商家；商家提交商品；管理员审核商品；用户下单；商家发货；用户收货和申请售后；商家处理退款；用户预约；管理员核销；关闭后端后切换演示模式并重复关键流程。

## 11. 迁移与交付

现有静态文件不继续扩展。迁移时在 `frontend/` 内建立 Vite 工程，将旧种子数据转为类型化 fixtures，并逐步替换旧页面。完成后删除不再引用的旧入口文件，更新 README、演示清单和技术说明。

交付物包括 Vue 源码、原创视觉资产、自动化测试、生产构建验证、桌面与移动端验收截图、更新后的运行说明。开发服务器启动后在 Chrome 中打开最终页面供用户检查；验证通过的提交推送至现有 GitHub 私有仓库。
